# Finding — the renderer drew the mirror image of its own model

Status: **fixed** — `fix/poster-north-up`
Found by: a visitor report on the deployed site, 2026-10-02 — hovering the
canvas named the wrong constellation while the figure table selected correctly
Severity: **High** — every canvas hover and every select-zoom on every sky was
wrong; the table path masked it because it uses direct indices.

## What happens

`project()` returns canvas-convention coordinates (down-positive,
north-negative — pinned by `astro.test.ts`'s "north-up" case), and the model
honours them (`py = DISK_CY + p.y * DISK_R`). But `unitToCanvas` applied a
math-to-canvas flip to that already-canvas input (`ay = cy − (v/AXIS)·half`),
so every drawn star, line and label sat mirrored vertically against the model.
Measured on a due-north star: the hit-test looks at y=228 (upper half) while
the blit draws it at y=576.

The figure table kept working because it passes indices, never coordinates —
which is exactly why "table correct, canvas wrong" is the signature of this
defect. Select-zoom was wrong the same way (the focus is a model centroid),
and the old e2e only asserted that a reset button appears, never where
anything is.

A second, smaller disagreement rode along: the model used a `DISK_R = 368`
literal while the drawing (and the ring) used `400 / 1.06 ≈ 377.36`, so cursor
and drawing drifted ~9px apart at the rim against a 12px hit tolerance.

## Why it was not caught, in the order it happened

**The reference suite guards the renderer against itself.** The stored PNGs are
generated by the same `unitToCanvas` they check, so a mirrored renderer
produces mirrored references and passes. Pixel comparison can never catch a
defect shared by both sides of the comparison.

**A unit test enshrined the mirror as intent.** `poster.test.ts` asserted
`unitToCanvas` "inverts y (matplotlib axes)": the author believed the input
was math-convention (y-up, as in matplotlib), but the real input has always
been canvas-convention. The test was true of the function and false of the
system.

**The labels hid the extent.** Label placement mapped the centroid back
through the preview with its own minus, so in the mirrored world the labels
landed near the model's (correct-side) positions while the lines sat mirrored
— every label detached from its own figure by up to the full mirror distance,
and nobody could tell by eye which layer was misplaced.

## What was done

- `unitToCanvas` preserves the sign (`cy + (v/AXIS)·half`); the two
  centroid back-conversions (composition labels, focus overlay) and the SVG
  exporter's copy invert with it, so labels sit exactly on their centroids.
- One scale: `AXIS_EXTENT` moved to `skymodel.ts` beside a derived
  `DISK_R = half / AXIS_EXTENT`; `poster.ts` re-exports it, and every
  `368` literal (`export.ts`, `reference.test.ts`) now reads the constant.
- All five reference PNGs regenerated (the sky is north-up, east-right:
  Ursa Major top, Orion east, Phoenix low south) and reviewed, not just
  re-blessed: Polaris (dec 89.26) draws at y=229.9, above centre.

## What is pinned now

- `site/src/lib/render/orientation.test.ts` — north draws above centre in
  both representations; `DISK_R` equals the ring scale; model pixels coincide
  with drawn pixels for synthetic stars (precision 9, so any future drift in
  either scale or sign fails); centroid round-trip lands on the centroid.
- `site/e2e/interactive.spec.ts` → "hovering draws the highlight where the
  cursor is": finds drawn content pixels in the northern band, hovers them,
  and asserts pixels near the cursor got brighter. Names alone cannot see
  this defect — the tooltip reads the model, so it is correct in both
  worlds — but a mirrored highlight lands far away, where the veil can only
  darken. A redrawn double-width segment crossing the 80px clip is hundreds
  of brightened pixels against a threshold of 40.
- The contract now states the orientation normatively
  (`contracts/render-spec.md` → Orientation).

## Found while pinning it

The hover tooltip (`.atlas-tooltip`, absolutely positioned over the top of the
poster) captured the pointer. Under a cursor hovering lines near the top of
the disc it fired `mouseleave` on the canvas, clearing the hover that showed
it — a flicker loop for visitors and a race for the new e2e journey (tooltip
visible at assert time, gone by read time). It is informational and duplicates
panel content, so it is `pointer-events: none` now.
